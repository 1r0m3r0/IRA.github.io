Open Banking y APIs Financieras

Conecta bancos, FinTechs y third-parties mediante APIs con OAuth 2.0

API Provider (Banco)

Los bancos exponen APIs REST con datos de cuentas, transacciones, saldos e iniciación de pagos. PSD2 obliga a abrir APIs en Europa desde 2018.

API Consumer (FinTech)

FinTechs y third parties consumen las APIs bancarias con consentimiento del usuario. Plaid conecta 12,000+ instituciones financieras en EE.UU.

OAuth 2.0

Estándar de autorización: el usuario da consentimiento, el banco emite un token de acceso. Scopes limitan el acceso (accounts.read, payments.write).

PSD2 vs PSD3

PSD2 (2018) obligó a abrir APIs. PSD3 (2025+) mejora: APIs estandarizadas, SCA simplificado, mejor protección al consumidor y más datos compartidos.

UK Open Banking

El estándar más maduro: especificaciones OBIE detalladas, CMA9 obligados a participar, 8M+ usuarios activos. Modelo seguido por Brasil, Australia y Japón.

Open Finance

Evolución de Open Banking: incluye seguros, inversiones, pensiones e hipotecas. Brasil lidera con el modelo más ambicioso de Open Finance en fases.

Ejemplo: Flujo OAuth 2.0 con una FinTech de Presupuesto

1
Usuario inicia conexión desde la FinTech

Pedro abre su app de presupuesto (YNAB/Mint) y selecciona "Conectar mi banco". La app redirige a Pedro a la página de login del banco. No comparte su contraseña bancaria con la FinTech.

2
Banco pide consentimiento (OAuth 2.0)

Pedro inicia sesión en el banco. El banco muestra: "YNAB solicita acceso a tus cuentas (read) y transacciones (read)". Pedro hace clic en "Autorizar". El banco genera un código de autorización temporal.

3
La FinTech intercambia el código por un token

YNAB envía el código de autorización + su client_id + client_secret al endpoint /token del banco. El banco valida y responde con un Access Token (JWT) + Refresh Token. El token expira en 90 minutos.

4
La FinTech llama a las APIs del banco

YNAB usa el Access Token en el header Authorization: Bearer para llamar a GET /accounts, GET /transactions. El banco devuelve datos JSON con cuentas y transacciones de Pedro. Scopes limitan el acceso.

5
Resultado: presupuesto automatizado

YNAB categoriza las transacciones automáticamente: $89.99 → "Compras", $1,200 → "Renta", $45 → "Transporte". Pedro ve su presupuesto sin ingresar datos manualmente. Todo funciona con Refresh Token para renovar el acceso.
