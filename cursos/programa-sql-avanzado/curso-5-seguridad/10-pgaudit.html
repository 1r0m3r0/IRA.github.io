📋 pgaudit

Auditoría detallada: logea DDL, DML, SELECT, ROLE, FUNCTION calls con pgaudit.

🎯 Piénsalo así: pgaudit es como las cámaras de seguridad de un banco. Cada acción queda registrada: quién entró, qué hizo, a qué hora, desde dónde. Así como las cámaras graban cada movimiento en la bóveda, pgaudit registra cada SELECT, INSERT, o comando DDL que ocurre en la base de datos. Cuando algo sale mal, revisas las grabaciones (logs).

¿Qué aprenderás?

  • A gestionar roles y permisos con CREATE ROLE y GRANT
  • A implementar seguridad a nivel de fila con Row-Level Security
  • A configurar autenticación con SCRAM-SHA-256 y SSL/TLS
  • A auditar actividades con pgAudit
  • A proteger la base de datos contra inyección SQL

Roles y Privilegios

PostgreSQL maneja permisos mediante roles. Los roles pueden ser usuarios (con LOGIN) o grupos (sin LOGIN). Los permisos se heredan a través de la membresía de roles.

CREATE ROLE analista LOGIN PASSWORD 'segura'; GRANT SELECT ON tablas TO analista;
⚠ NUNCA uses contraseñas débiles en producción

Row-Level Security

RLS permite restringir qué filas puede ver o modificar cada usuario basado en una política. Es como un WHERE automático que PostgreSQL añade a cada consulta.

CREATE POLICY solo_propios ON pedidos USING (cliente_id = current_user_id());
⚠ RLS funciona incluso si el usuario tiene SELECT en la tabla

SSL/TLS

PostgreSQL soporta conexiones cifradas con SSL/TLS. El servidor puede requerir certificados del cliente para autenticación mutua.

ssl = on ssl_cert_file = 'server.crt' ssl_key_file = 'server.key'
⚠ Usa certificados de Let's Encrypt o una CA interna

pgAudit

La extensión pgAudit permite auditar todas las operaciones de la base de datos a nivel de sesión u objeto. Genera logs detallados de cada comando ejecutado.

CREATE EXTENSION pgaudit; SET pgaudit.log = 'write,ddl';
⚠ Configura la rotación de logs para evitar llenar el disco

SCRAM-SHA-256

El método de autenticación más seguro en PostgreSQL. Reemplaza al antiguo MD5. SCRAM almacena un hash salado y utiliza un protocolo de desafío-respuesta.

password_encryption = 'scram-sha-256' CREATE ROLE usuario LOGIN PASSWORD 'pass';
⚠ Migra de MD5 a SCRAM con ALTER SYSTEM y pg_reload_conf

Protección contra Inyección SQL

La mejor defensa es usar consultas parametrizadas. Nunca concatenes Input de usuario en SQL. Usa sentencias preparadas o funciones con parámetros.

PREPARE busca (INT) AS SELECT * FROM usuarios WHERE id = $1; EXECUTE busca(42);
⚠ Las funciones PL/pgSQL también protegen contra inyección

Ejemplo paso a paso

1

Crea roles con diferentes niveles de acceso para tu aplicación

CREATE ROLE app_readonly LOGIN PASSWORD 'read123'; CREATE ROLE app_writer LOGIN PASSWORD 'write456'; CREATE ROLE admin LOGIN PASSWORD 'admin789' SUPERUSER;
2

Otorga permisos específicos a cada rol según sus necesidades

GRANT SELECT ON ALL TABLES IN SCHEMA public TO app_readonly; GRANT SELECT, INSERT, UPDATE ON ALL TABLES IN SCHEMA public TO app_writer;
3

Configura RLS para que los usuarios solo vean sus propios datos

ALTER TABLE pedidos ENABLE ROW LEVEL SECURITY; CREATE POLICY pedidos_propios ON pedidos USING (usuario_id = current_setting('app.usuario_id')::INT);
4

Habilita SSL/TLS y verifica la conexión segura

openssl req -new -x509 -days 365 -nodes -out server.crt -keyout server.key chmod 600 server.key -- En postgresql.conf: ssl = on ssl_cert_file = 'server.crt' ssl_key_file = 'server.key'
5

Verifica quién está conectado y qué permisos tiene

SELECT usename, application_name, client_addr, ssl FROM pg_stat_activity WHERE state = 'active'; SELECT * FROM information_schema.table_privileges WHERE grantee = 'app_readonly';

🎯 ¿Qué aprenderás?

  • Comprender el concepto fundamental de SQL explicado en este módulo
  • Aplicar la sintaxis correcta con ejemplos prácticos de consultas
  • Evitar errores comunes y optimizar el rendimiento
  • Desarrollar intuición para elegir la técnica adecuada

📋 Consola de Auditoría pgaudit

📋 Auditoría desactivada
shared_preload_libraries = ''
💡 Interactúa con los controles
💬 pgaudit es la extensión de auditoría oficial de PostgreSQL. Se configura con pgaudit.log (qué operaciones auditar: DDL, DML, ROLE, etc.) y pgaudit.log_level. Cada operación auditada genera una entrada en el log de PostgreSQL con el usuario, la consulta, los parámetros y el timestamp.
