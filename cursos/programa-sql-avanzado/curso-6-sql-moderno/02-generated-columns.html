🧮 GENERATED COLUMNS

Columnas generadas almacenadas y virtuales. Campos calculados que se actualizan automáticamente.

🎯 Piénsalo así: Las columnas generadas son como el total en una factura. No escribes el total manualmente; se calcula automáticamente a partir de los subtotales. Si cambias un precio, el total se actualiza solo. Así funcionan las GENERATED COLUMNS: definidas por una expresión, se recalculan automáticamente cuando cambian los datos de los que dependen.

¿Qué aprenderás?

  • A usar MERGE y UPSERT para sincronización de datos
  • A crear columnas generadas para datos derivados
  • A usar GROUPING SETS, ROLLUP y CUBE para análisis multidimensional
  • A implementar tablas temporales con SYSTEM VERSIONING
  • A realizar búsquedas vectoriales con pgvector

MERGE (UPSERT)

INSERT ... ON CONFLICT (UPSERT) permite insertar o actualizar en una sola operación. Si el registro existe por la clave primaria, se actualiza; si no, se inserta.

INSERT INTO inventario (id, producto, stock) VALUES (1, 'Laptop', 10) ON CONFLICT (id) DO UPDATE SET stock = inventario.stock + EXCLUDED.stock;
⚠ EXCLUDED referencia los valores que se intentaron insertar

Columnas Generadas

Las columnas generadas (STORED o VIRTUAL) se calculan automáticamente a partir de otras columnas. PostgreSQL 12+ soporta STORED, que guarda físicamente el valor.

CREATE TABLE productos ( precio NUMERIC, iva NUMERIC GENERATED ALWAYS AS (precio * 0.16) STORED );
⚠ Las columnas generadas no se pueden modificar directamente

GROUPING SETS

GROUPING SETS, ROLLUP y CUBE permiten múltiples agrupaciones en una sola consulta. Más eficiente que hacer UNION de varios GROUP BY.

SELECT año, mes, SUM(ventas) FROM ventas GROUP BY GROUPING SETS ((año), (año, mes), ());
⚠ El orden de las columnas afecta los resultados de ROLLUP

Tablas Temporales

PostgreSQL no tiene tablas temporales del sistema (como SQL:2011), pero se puede emular con triggers o extensiones como temporal_tables.

-- Con extensión temporal_tables: CREATE EXTENSION temporal_tables; SELECT version_sys_period(pedidos);
⚠ Las tablas versionadas permiten consultar el estado en cualquier momento

pgvector

La extensión pgvector permite almacenar y buscar vectores de embeddings directamente en PostgreSQL. Soporta distancia coseno, L2 e inner product.

CREATE EXTENSION vector; CREATE TABLE items (id INT, embedding VECTOR(3)); SELECT * FROM items ORDER BY embedding <=> '[1,2,3]' LIMIT 5;
⚠ Usa índices IVFFlat para acelerar búsquedas en más de 1000 vectores

LATERAL Joins

LATERAL permite que una subconsulta en FROM haga referencia a columnas de tablas anteriores en la misma cláusula FROM. Ideal para top-N por grupo.

SELECT * FROM usuarios u, LATERAL (SELECT * FROM pedidos WHERE usuario_id = u.id ORDER BY fecha DESC LIMIT 3) p;
⚠ LATERAL se ejecuta como un bucle correlacionado optimizado

Ejemplo paso a paso

1

Crea una tabla de ejemplo con datos maestros para practicar operaciones modernas

CREATE TABLE ventas ( id SERIAL PRIMARY KEY, producto TEXT, categoria TEXT, monto NUMERIC, fecha DATE ); INSERT INTO ventas VALUES (1, 'Laptop', 'Electrónica', 1500, '2026-01-15'), (2, 'Mouse', 'Electrónica', 25, '2026-01-16');
2

Usa MERGE para sincronizar datos desde una tabla de staging

MERGE INTO ventas AS v USING (VALUES (1, 'Laptop Pro', 1600), (3, 'Teclado', 80)) AS s(id, producto, monto) ON v.id = s.id WHEN MATCHED THEN UPDATE SET producto = s.producto, monto = s.monto WHEN NOT MATCHED THEN INSERT (id, producto, monto, fecha) VALUES (s.id, s.producto, s.monto, CURRENT_DATE);
3

Usa GROUPING SETS para analizar ventas por múltiples dimensiones

SELECT categoria, producto, SUM(monto) as total FROM ventas GROUP BY GROUPING SETS ( (categoria), (categoria, producto), () ) ORDER BY categoria NULLS LAST, producto NULLS LAST;
4

Agrega una columna generada para calcular IVA automáticamente

ALTER TABLE ventas ADD COLUMN iva NUMERIC GENERATED ALWAYS AS (monto * 0.16) STORED; SELECT * FROM ventas; -- El IVA se calcula automáticamente
5

Usa pgvector para búsqueda semántica de productos similares

CREATE EXTENSION IF NOT EXISTS vector; ALTER TABLE ventas ADD COLUMN embedding VECTOR(3); UPDATE ventas SET embedding = '[0.5,0.3,0.8]' WHERE id = 1; UPDATE ventas SET embedding = '[0.1,0.9,0.2]' WHERE id = 2; SELECT producto, monto FROM ventas ORDER BY embedding <=> '[0.4,0.4,0.7]' LIMIT 3;

  • Comprender el concepto fundamental de SQL explicado en este módulo
  • Aplicar la sintaxis correcta con ejemplos prácticos de consultas
  • Evitar errores comunes y optimizar el rendimiento
  • Desarrollar intuición para elegir la técnica adecuada

🧮 Constructor de Columnas Generadas

CREATE TABLE productos (
id SERIAL PRIMARY KEY,
nombre TEXT,
precio DECIMAL(10,2),
precio_iva DECIMAL(10,2) GENERATED ALWAYS AS (precio * 1.21) STORED
);
💡 Interactúa con los controles
💬 GENERATED ALWAYS AS (expresión) STORED crea una columna que se calcula automáticamente y se almacena en disco. VIRTUAL (SQL:2023, aún no en PostgreSQL) se calcula en lectura. STORED ocupa espacio pero acelera lecturas. No se puede INSERTAR o UPDATEar directamente.
