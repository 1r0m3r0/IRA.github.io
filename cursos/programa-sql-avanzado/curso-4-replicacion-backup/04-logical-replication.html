🔗 Logical Replication

Replicación lógica: publica tablas, suscríbete entre versiones y haz upgrades sin downtime.

🎯 Piénsalo así: La replicación lógica es como una suscripción a una revista. El publicador (publisher) prepara artículos específicos (tablas) y los suscriptores (subscribers) reciben solo esos artículos, no la revista completa. Puedes tener la revista en español (PostgreSQL 15) y otro suscriptor en inglés (PostgreSQL 16).

¿Qué aprenderás?

  • A configurar WAL para durabilidad y Point-In-Time Recovery
  • A implementar streaming replication para alta disponibilidad
  • A realizar backups con pg_basebackup y pgbackrest
  • A configurar failover automático con herramientas de clustering
  • A recuperar una base de datos a un punto exacto en el tiempo

WAL Segments

Los archivos WAL (por defecto 16 MB cada uno) almacenan todos los cambios antes de aplicarse a los datos. PostgreSQL escribe en WAL secuencialmente para máximo rendimiento.

SHOW wal_segment_size; -- 16777216 (16MB)
⚠ Aumenta el tamaño en sistemas con mucha escritura

Checkpoints

Los checkpoints fuerzan que todos los buffers sucios en memoria se escriban a disco. PostgreSQL ajusta automáticamente la frecuencia basado en el volumen de WAL generado.

SHOW checkpoint_completion_target; -- 0.9
⚠ checkpoint_timeout controla la frecuencia máxima

Archivado WAL

El archivado WAL (archive_mode = on) permite copiar segmentos WAL a un almacenamiento externo para PITR y replicación.

archive_command = 'cp %p /backups/%f'
⚠ Comprime WALs viejos con gzip para ahorrar espacio

Redo y Undo

PostgreSQL solo implementa REDO (rehacer) desde WAL. No necesita UNDO porque usa MVCC: las versiones viejas de filas permanecen en el heap hasta que VACUUM las limpia.

-- PostgreSQL no tiene UNDO LOG como Oracle
⚠ El WAL solo contiene datos para REDO, simplificando el diseño

Full Page Writes

En el primer cambio después de un checkpoint, PostgreSQL escribe la página completa en WAL. Esto evita páginas corruptas durante la recuperación tras un crash.

SHOW full_page_writes; -- on
⚠ Causa WAL más grande pero garantiza recuperación segura

WAL y Replicación

Los segmentos WAL son la base de la replicación física. El standby lee el WAL del primario y aplica los mismos cambios, manteniendo una copia idéntica.

SELECT * FROM pg_stat_replication;
⚠ El WAL también se usa para replicación lógica con Decodificación Lógica

Ejemplo paso a paso

1

Verifica la configuración actual del WAL en tu instancia

SHOW wal_level; SHOW wal_buffers; SHOW wal_segment_size;
2

Revisa el estado de los checkpoints y la generación de WAL

SELECT * FROM pg_stat_checkpoints ORDER BY checkpoint_time DESC LIMIT 5;
3

Monitorea el tamaño total del directorio pg_wal en el servidor

SELECT pg_size_pretty(SUM(size)) as total_wal FROM pg_ls_waldir();
4

Habilita el archivado WAL para backup continuo

ALTER SYSTEM SET archive_mode = 'on'; ALTER SYSTEM SET archive_command = 'cp %p /backups/wal/%f'; SELECT pg_reload_conf();
5

Simula una recuperación restaurando desde un backup base + WAL

# En recovery.conf (o postgresql.auto.conf): restore_command = 'cp /backups/wal/%f %p' recovery_target_time = '2026-06-15 14:30:00'

  • Comprender el concepto fundamental de SQL explicado en este módulo
  • Aplicar la sintaxis correcta con ejemplos prácticos de consultas
  • Evitar errores comunes y optimizar el rendimiento
  • Desarrollar intuición para elegir la técnica adecuada

💡 Interactúa con los controles de arriba
💬 La replicación lógica replica cambios a nivel de fila (usando el decode plugin pgoutput). A diferencia de la replicación física, permite replicar tablas individuales entre diferentes versiones de PostgreSQL, hacer upgrades sin downtime, y replicar bidireccionalmente.
