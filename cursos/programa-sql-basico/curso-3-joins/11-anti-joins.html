Anti-Joins

Módulo 11 Â· Joins

¿Qué aprenderás?

  • Entender qué son los anti-joins
  • Usar NOT EXISTS y NOT IN
  • Usar LEFT JOIN ... IS NULL
  • Aplicar anti-joins para exclusión

🧠 Intuición

Anti-join es lo opuesto a INNER JOIN: encuentra filas que NO tienen correspondencia. 'Dame los clientes que NO han hecho pedidos'.

Hay tres formas: NOT EXISTS, NOT IN, y LEFT JOIN ... IS NULL. Cada una tiene sus ventajas y riesgos.

NOT EXISTS es la más segura y recomendada.

📝 Sintaxis

SELECT * FROM a WHERE NOT EXISTS (SELECT 1 FROM b WHERE a.id = b.a_id);

SELECT * FROM a WHERE id NOT IN (SELECT a_id FROM b);

SELECT a.* FROM a LEFT JOIN b ON a.id = b.a_id WHERE b.id IS NULL;

💻 Ejemplo

-- Clientes sin pedidos (recomendado)
SELECT * FROM clientes c WHERE NOT EXISTS (SELECT 1 FROM pedidos p WHERE p.cliente_id = c.id);

-- Productos nunca vendidos
SELECT * FROM productos p WHERE NOT EXISTS (SELECT 1 FROM ventas v WHERE v.producto_id = p.id);

⚠️ Errores

NOT IN con NULL: si la subconsulta devuelve NULL, el resultado es vacío. Siempre.

LEFT JOIN ... IS NULL puede ser más lento en tablas grandes.

NOT EXISTS es generalmente la más segura y eficiente.

🔍 Dato

NOT EXISTS corta la ejecución en cuanto encuentra la primera coincidencia.

PostgreSQL optimiza NOT EXISTS muy bien.

En SQL Server, NOT IN puede ser problemático con NULL.

🎯 Clave

Anti-join = filas que NO se corresponden.

NOT EXISTS es la forma recomendada.

NOT IN es peligroso con NULL.

LEFT JOIN ... IS NULL es la forma visual.

Ejemplo Paso a Paso

-- Las 3 formas de anti-join:

-- Forma 1: NOT EXISTS (recomendada)
SELECT * FROM clientes c WHERE NOT EXISTS (SELECT 1 FROM pedidos p WHERE p.cliente_id = c.id);

-- Forma 2: LEFT JOIN ... IS NULL
SELECT c.* FROM clientes c LEFT JOIN pedidos p ON c.id = p.cliente_id WHERE p.id IS NULL;

-- Forma 3: NOT IN (cuidado con NULL)
SELECT * FROM clientes WHERE id NOT IN (SELECT cliente_id FROM pedidos);

Concepto

Un Anti-Join encuentra filas en una tabla que NO tienen correspondencia en la otra. Se logra con LEFT JOIN ... WHERE ... IS NULL o NOT EXISTS.

-- Clientes sin pedidos
SELECT clientes.*
FROM clientes
LEFT JOIN pedidos ON clientes.id = pedidos.cliente_id
WHERE pedidos.id IS NULL;
Analogía: Anti-Join es como buscar estudiantes que NO entregaron la tarea: tienes la lista de todos los estudiantes (izquierda), buscas quiénes tienen tarea (derecha), y te quedas con los que NO aparecen en la lista de tareas.

Resumen del Módulo

Los anti-joins encuentran filas sin correspondencia. NOT EXISTS es la forma más segura y recomendada. NOT IN es riesgoso con NULL. LEFT JOIN ... IS NULL es clara visualmente. Anti-joins son esenciales para encontrar datos huérfanos o excluir categorías.
