🆔 SERIAL / IDENTITY / UUID

Tres formas de generar identificadores únicos automáticos

💡 Piénsalo así: Los IDs son como las placas de los coches: cada uno debe ser único. SERIAL es como una placa secuencial (001, 002, 003). IDENTITY es similar pero más estándar SQL. UUID es como una placa con un código gigante imposible de adivinar (los números de bastidor). UUID es perfecto para sistemas distribuidos donde varios servidores crean IDs sin coordinarse.

¿Qué aprenderás?

  • Conocer SERIAL para autoincremento
  • Usar IDENTITY (SQL estándar)
  • Entender UUID como alternativa
  • Elegir la estrategia de IDs adecuada

🧠 Intuición

SERIAL es como un contador automático que asigna 1, 2, 3... a cada nueva fila. IDENTITY es la versión estándar SQL de lo mismo. UUID genera identificadores únicos universales (como 'abc123...' de 36 caracteres).

SERIAL es simple y eficiente pero solo único dentro de la tabla. UUID es único globalmente (útil para sistemas distribuidos) pero ocupa más espacio.

📝 Estrategias

SERIAL: autoincremental (1, 2, 3...). PostgreSQL: SMALLSERIAL, SERIAL, BIGSERIAL.

IDENTITY: estándar SQL: GENERATED ALWAYS AS IDENTITY.

UUID: identificador único de 128 bits: gen_random_uuid().

💻 Ejemplo

id SERIAL PRIMARY KEY — autoincremental.

id INTEGER GENERATED ALWAYS AS IDENTITY — estándar.

id UUID DEFAULT gen_random_uuid() PRIMARY KEY — UUID.

⚠️ Errores

SERIAL no previene huecos (si se elimina una fila, el número no se reusa).

SERIAL no es único entre tablas (cada tabla tiene su propio contador).

UUID es más lento como PK porque es más grande y aleatorio.

🔍 Dato

PostgreSQL 10+ tiene IDENTITY (más estándar que SERIAL).

UUID es ideal para sistemas distribuidos o microservicios.

SERIAL ocupa 4 bytes, UUID ocupa 16 bytes.

🎯 Clave

SERIAL = autoincremental simple.

IDENTITY = estándar SQL moderno.

UUID = único globalmente.

SERIAL es suficiente para la mayoría de casos.

Ejemplo Paso a Paso

-- Opción 1: SERIAL (PostgreSQL clásico)
CREATE TABLE clientes (id SERIAL PRIMARY KEY, nombre TEXT);

-- Opción 2: IDENTITY (estándar SQL)
CREATE TABLE clientes (id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY, nombre TEXT);

-- Opción 3: UUID
CREATE TABLE clientes (id UUID DEFAULT gen_random_uuid() PRIMARY KEY, nombre TEXT);
