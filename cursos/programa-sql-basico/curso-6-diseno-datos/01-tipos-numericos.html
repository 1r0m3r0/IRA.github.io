🔢 Tipos Numéricos

Enteros, decimales y números de precisión arbitraria

🧠 Intuición

Los tipos numéricos son como diferentes tamaños de recipientes. INTEGER es una taza medidora (números sin decimales). DECIMAL es una báscula de precisión (con decimales exactos). NUMERIC es una báscula científica de alta precisión.

Usar el tipo correcto ahorra espacio y evita errores de redondeo. Un SMALLINT ocupa 2 bytes, un INTEGER 4, un BIGINT 8.

📝 Tipos Numéricos

SMALLINT: 2 bytes, -32K a +32K.

INTEGER: 4 bytes, -2B a +2B.

BIGINT: 8 bytes, -9Q a +9Q.

DECIMAL(p,s): exacto, p dígitos, s decimales.

NUMERIC(p,s): exacto, igual que DECIMAL.

REAL: 4 bytes, aproximado.

DOUBLE: 8 bytes, aproximado.

💻 Ejemplo

Edad: SMALLINT es suficiente (0-150).

Precio: DECIMAL(10,2) para exactitud con 2 decimales.

Población mundial: BIGINT.

Promedio: REAL o DOUBLE es aceptable.

⚠️ Errores

Usar INTEGER para precios: pierdes los decimales.

Usar DECIMAL sin especificar decimales: DECIMAL(10,0) = solo enteros.

Usar REAL para dinero: errores de redondeo.

🔍 Dato

PostgreSQL tiene tipos adicionales: SMALLSERIAL, SERIAL, BIGSERIAL.

NUMERIC y DECIMAL son sinónimos en PostgreSQL.

DOUBLE se llama DOUBLE PRECISION en PostgreSQL.

🎯 Clave

Elige el tipo según el rango y precisión.

DECIMAL/NUMERIC para dinero (exactos).

INTEGER/BIGINT para conteos.

REAL/DOUBLE para aproximaciones.

Ejemplo Paso a Paso

-- Paso 1: Crear tabla con tipos numéricos
CREATE TABLE productos (
id SERIAL PRIMARY KEY, -- entero autoincremental
precio DECIMAL(10,2) NOT NULL, -- exacto, 2 decimales
stock INTEGER DEFAULT 0, -- entero
peso REAL -- aproximado
);

-- DECIMAL(10,2) = 8 dígitos enteros + 2 decimales
-- Rango: -99999999.99 a 99999999.99
