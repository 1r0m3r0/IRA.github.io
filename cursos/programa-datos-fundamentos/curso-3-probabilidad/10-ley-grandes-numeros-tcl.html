▶ Preparacion de Datos en Teorema Central del Limite
Intuicion

Preparar datos es como lavar y cortar verduras antes de cocinar. Por muy buena que sea tu receta, si los ingredientes estan sucios o mal cortados, el plato final sera decepcionante. Esta fase consume el 60-80% del tiempo de un proyecto de datos, y es donde se toman las decisiones mas importantes.

Codigo paso a paso
Las operaciones tipicas incluyen: df.dropna() para eliminar nulos, df.fillna(valor) para imputar, pd.to_datetime() para fechas, df.astype() para tipos. Crea una pipeline de limpieza con funciones modulares que puedas reutilizar en diferentes proyectos.
Ejemplo practico

Un dataset de clientes tiene edades negativas y salarios con comas. Aplicas: df['edad'] = df['edad'].abs() para corregir signos, df['salario'] = df['salario'].str.replace(',','').astype(float) para limpiar formato, y validas que los rangos sean logicos.

Errores comunes

Error comun: modificar los datos originales sin backup. Otro: asumir formatos consistentes entre columnas. Clave: documentar cada transformacion y su justificacion para reproducibilidad.

▶ Optimizacion y Rendimiento en Teorema Central del Limite
Intuicion

Optimizar codigo de datos es como ajustar un motor: no necesitas maxima velocidad siempre, pero cuando trabajas con millones de registros, cada milisegundo cuenta. La clave esta en medir antes de optimizar y enfocarse en los cuellos de botella reales.

Codigo paso a paso
Mide con %timeit o time.perf_counter(). Luego optimiza: prefiere operaciones vectorizadas sobre bucles, usa.query() en lugar de mascaras booleanas complejas, elige el tipo de dato mas pequeno posible (int8 vs int64) cuando los valores lo permitan.
Ejemplo practico

Un bucle que procesa 1 millon de filas puede tomar 45 segundos. Usando operaciones vectorizadas de NumPy, el mismo calculo toma 0.3 segundos. Con paralelizacion via joblib, podria bajar a 0.1 segundos. La diferencia entre codigo amateur y profesional.

Errores comunes

Optimizar prematuramente sin identificar cuellos de botella reales es perdida de tiempo. Tampoco sacrifiques legibilidad por velocidad micro-op timizations. Y recuerda: la optimizacion cambia segun el volumen de datos.

▶ Errores Tipicos y Depuracion en Teorema Central del Limite
Intuicion

Depurar codigo de datos es parte natural del proceso, no una senal de fracaso. Los errores mas comunes incluyen problemas de tipos de datos, valores nulos inesperados, indexacion incorrecta y suposiciones erroneas sobre el formato de los datos. Cada error es una oportunidad de aprendizaje.

Codigo paso a paso
Usa try/except para manejar errores esperados, assert para validar supuestos y logging en lugar de print para seguimiento. Configura warnings.filterwarnings('error') para convertir warnings en errores detectables durante desarrollo.
Ejemplo practico

ValueError: cannot convert float NaN to integer. Ocurre al convertir columna con nulos a entero. Solucion: imputa antes con df['col'].fillna(0).astype(int). Otro comun: KeyError al referenciar columna que no existe por cambio de nombre previo.

Errores comunes

Ignorar warnings porque 'no pasa nada' hasta que produce resultados incorrectos. No probar con datos limite (vacios, todos nulos, valores extremos). Asumir que funciona igual con datos grandes que con datos pequenos.
